# Bhumi Vikas Sahayak: Backend

This is an evidence-grounded question-answering API for the **Madhya Pradesh Bhumi Vikas Rules, 2012**, as consolidated up to **6 March 2025**. Answers come with citations that are checked verbatim against the source text. If the rules don't answer a question, the API says so.

The frontend contract is in [`API_CONTRACT.md`](./API_CONTRACT.md).

## Quickstart

Run everything from the **repository root**, because the imports are `backend.app...`.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate      Linux/macOS: source .venv/bin/activate
pip install -r backend/requirements.txt

cp backend/.env.example backend/.env    # backend/.env is git-ignored; add CEREBRAS_API_KEY
python -m backend.app.tools.check_cerebras --chat   # optional: verify key and model
uvicorn backend.app.main:app --reload --port 8000
```

- API: `http://localhost:8000`
- Swagger UI: `http://localhost:8000/docs`
- Health check: `http://localhost:8000/health` (`"provider": "cerebras"`; `"status": "degraded"` means the key is missing)

## Cerebras Cloud (LLM provider)

Answers are generated by Cerebras Cloud through its OpenAI-compatible API (`https://api.cerebras.ai/v1`), using the `openai` Python SDK.

### 1. Get an API key

1. Sign in at <https://cloud.cerebras.ai>.
2. Open **API Keys** and create a key. Keys start with `csk-`.
3. Treat the key as a password. It belongs only in `backend/.env` or the server's environment. Never put it in frontend code or in a `VITE_*` or `REACT_APP_*` variable, because those are bundled into the browser.

### 2. Configure `backend/.env`

```ini
LLM_PROVIDER=cerebras
CEREBRAS_API_KEY=            # paste your key after the = sign
CEREBRAS_MODEL=              # empty = gpt-oss-120b
```

| Variable | Default | Meaning |
|---|---|---|
| `CEREBRAS_API_KEY` | — | Required. Only the backend reads it, from `backend/.env` or the environment. It is never logged or returned. |
| `CEREBRAS_MODEL` | `gpt-oss-120b` | A model ID your account can use. The shared-inference models listed in the [Cerebras docs](https://inference-docs.cerebras.ai/models/overview) on 2026-10-11 were `gpt-oss-120b` and `qwen-3.8-27b`, and both support the strict JSON-schema output this backend uses. Run `python -m backend.app.tools.check_cerebras` to list the models available to your key. |
| `CEREBRAS_REASONING_EFFORT` | model default | `low`, `medium` or `high` on `gpt-oss-120b`; `none` turns reasoning off on `qwen-3.8-27b`. Lower effort is faster and leaves more of the token budget for the answer. |
| `CEREBRAS_TEMPERATURE` | model default | A value from 0 to 2. |
| `CEREBRAS_MAX_COMPLETION_TOKENS` | `4096` | The output cap. On reasoning models it **includes reasoning tokens**. |
| `CEREBRAS_MAX_RETRIES` | `2` | The SDK retries connection errors, 408, 429 and 5xx responses with exponential backoff. |
| `LLM_TIMEOUT_SECONDS` | `60` | The timeout for each attempt. |

Environment variables override `backend/.env`. In production, set them in the host's secret store instead of a file.

### 3. What is sent to Cerebras

Only passages that retrieval rates above the "low" relevance band are sent. If no passage qualifies, the API returns the insufficient-evidence response **without calling Cerebras**, so the model cannot fill gaps from general knowledge.

The request contains three things:
- a grounding system prompt;
- the question and numbered passages, each escaped and wrapped in `<untrusted_document_context>` tags;
- a strict `response_format` JSON schema: `answer`, `confidence`, `insufficient_evidence`, and `citations: [{passage_id, quote}]`.

The model only says *which passage* it relied on and quotes it. The rule number, PDF page and document title come from the retrieval record. A quote that is not verbatim in that passage is dropped, and if no citation survives, the generated answer is withheld (`insufficient_evidence: true`).

The system prompt requires the model to:
- answer in the requested language;
- keep conditions and exceptions;
- never invent rule numbers or figures;
- quote rule text separately from its own explanation;
- say when the evidence is incomplete or ambiguous;
- never present an answer as a building-plan approval.

### 5. Troubleshooting

If Cerebras fails, `/api/chat` still returns `200`. The answer then starts with "The AI answer service is currently unavailable…", or with "The AI service has reached its usage limit…" for rate limits. `confidence` is `"low"`, and the response contains only verified source passages, so nothing is generated. No other provider is tried. The server log names the cause with a `reason` code.

**Rate limits are the most likely failure.** The key used during development reported these limits in its response headers (checked 2026-10-11):

| Limit | Value |
|---|---|
| Requests | 5 per minute, 150 per hour, 2,400 per day |
| Tokens | 30,000 per minute |

A chat question costs 1 request. A document upload costs 1 request plus 1 per page that needs OCR (at most `UPLOAD_MAX_OCR_PAGES`, default 3).

When Cerebras returns a long `retry-after` (about 60 s once the per-minute quota is used up), the backend answers immediately with the fallback rather than holding the request. The worst case per answer is (2 retries + 1) × 20 s + 2 × 5 s = 70 s, which stays below the frontend's 90 s timeout.

| Log `reason` | Typical cause | Fix |
|---|---|---|
| `not_configured` | `CEREBRAS_API_KEY` is empty, or `openai` is not installed | Set the key in `backend/.env`, then restart; run `pip install -r backend/requirements.txt` |
| `auth` (401/403) | The key is wrong, revoked, or has no access to the model | Create a new key and check that it was copied without spaces |
| `model_not_found` (404) | `CEREBRAS_MODEL` is not available to your account | Run `python -m backend.app.tools.check_cerebras` and pick a listed ID |
| `bad_request` (400/422) | The model rejects a parameter (`response_format`, `reasoning_effort`, `temperature`) | Clear `CEREBRAS_REASONING_EFFORT` and `CEREBRAS_TEMPERATURE`, or try another model |
| `rate_limited` (429) | The per-minute, hourly or daily quota was used up (`code=request_quota_exceeded`) | Wait a minute, send fewer requests, or upgrade the plan |
| `billing` (402) | A payment or plan problem | Check billing in the Cerebras console |
| `timeout` / `network` | Slow responses or no connectivity to `api.cerebras.ai` | Check the network or proxy; raise `CEREBRAS_TIMEOUT_SECONDS` |
| `truncated` | The output hit `CEREBRAS_MAX_COMPLETION_TOKENS`, which includes reasoning | Raise the cap or lower `CEREBRAS_REASONING_EFFORT` |
| `server_error` (5xx) | A Cerebras-side problem | Retry later |

Log lines include the HTTP status, the Cerebras error code and the request ID, but never the key or the provider's raw error text.

## Document upload (`POST /api/documents/analyze`)

A user can attach their own document, such as a building plan, application, notice or letter, and ask about it. The backend reads the document and answers against the rules using the same retrieval, citation checks and uncertainty handling as chat. Uploaded documents are **never stored** and are **not** added to the rule database.

**Reading the document** (`services/document_reader.py`):

| Input | How it is read |
|---|---|
| Digital PDF | The PDF's text layer (`pypdf`). |
| Scanned PDF page, or a page whose text layer is in the legacy Kruti Dev Hindi font or has broken characters | The page is rendered with `pypdfium2` and read by OCR. |
| PNG, JPEG or WebP photo | OCR. |
| Plain text (UTF-8) | Read as-is. |

OCR uses Cerebras vision (`CEREBRAS_VISION_MODEL`, default `qwen-3.8-27b`; a live test on 2026-10-11 confirmed this model accepts images on the development key). AI-based OCR can misread text: one test image produced "सुड़क" for "सड़क". So OCR results are labelled `ocr_is_generative: true`, and the answer tells the user to check figures against their original.

Safety measures:
- The file type is detected from the content, not the extension.
- Limits: `UPLOAD_MAX_BYTES` (10 MB), `UPLOAD_MAX_PAGES` (30), `UPLOAD_MAX_OCR_PAGES` (3), `UPLOAD_MAX_TEXT_CHARS` (24,000). Images over 40 MP and password-protected PDFs are rejected.
- Everything is processed in memory.

**Answering:**
- Rule passages are retrieved for both the question and the document's own words. Bare numbers are left out of the document search, because they made unrelated documents, such as a cricket scorecard, match rule tables.
- The model receives the document fenced as `<untrusted_uploaded_document>`. It is told never to call a plan approved, compliant or rejected, in English or Hindi.
- Statements about the user's document come back as `document_quotes`, each verified verbatim against the extracted text of the stated page.
- Figures taken from the user's document are allowed in the answer. Figures attributed to the rules must still appear in the cited rule excerpts.

Test it:
```bash
curl -s -X POST localhost:8000/api/documents/analyze \
     -F "file=@plan.pdf" -F "question=Is the proposed front open space enough?" -F "language=en"
curl -s localhost:8000/api/documents/limits
```

The frontend attaches files with the paperclip button in either input box.

## Other providers

The server also works with no LLM at all. In that case it runs in **retrieval-only** (`extractive`) mode and returns the verified passages most relevant to each question. Other providers can be selected with `LLM_PROVIDER`:

| `LLM_PROVIDER` | Needs | Notes |
|---|---|---|
| `cerebras` | `CEREBRAS_API_KEY` | See above. This is the value set in `.env.example`. |
| `extractive` (code default) | nothing | No LLM. Returns quoted source passages only. |
| `anthropic` | `ANTHROPIC_API_KEY` | Uses the official `anthropic` SDK. The default model is `claude-opus-5-5`; `ANTHROPIC_EFFORT` sets depth. Server-side refusal fallback is on by default (`ANTHROPIC_ENABLE_FALLBACKS`). |
| `openai` | `OPENAI_API_KEY` | Works with any OpenAI-compatible endpoint via `OPENAI_BASE_URL`. |
| `gemini` | `GEMINI_API_KEY` | Uses the Gemini REST API. The key is sent in a header, not the URL. |

If `LLM_PROVIDER` is set to an unknown value, startup fails with a clear error. The old value `mock` is still accepted and means `extractive`.

## How it works

```
question ──► out-of-scope check ──► hybrid retrieval (BM25 + TF-IDF) ──► relevant passages?
                                                                          │ none → "not found" (no LLM call)
                                               ┌──────────────────────────┤
                                               ▼                          ▼
                                      retrieval-only answer     LLM (Cerebras): JSON answer +
                                      (no LLM / LLM failed)     citations [{passage_id, quote}]
                                                                              │
                     citation builder: quote must be verbatim in that passage ◄┘
                     rule, page, title from the retrieval record (never from the model)
                     numbers in the answer must appear in the cited text
                     known post-coverage amendments → freshness note
```

- **Ingestion** (`services/document_store.py`). `data/bhumi_vikas_rules.jsonl` provides 106 rules (1–105 plus 26-B). Each rule is split at its running page headers and then into paragraphs and sub-clauses, and table column-header rows stay with their table. `data/bhumi_vikas_rules_fulltext_by_page.txt` provides a per-page index that resolves the PDF page of any verified excerpt. The page numbers printed in the headers were checked against the PDF page numbers for pages 2–108.
- **Retrieval** (`services/retriever.py`). BM25 (60%) and TF-IDF over 1–3-grams (40%) are combined with light plural stemming. Bonuses are added for title coverage and for direct references such as "Rule 56" or "नियम 23". Hindi questions are mapped to English rule vocabulary through a domain glossary, because the Hindi PDF cannot be text-indexed (see the limitations below).
- **Generation** (`services/rag_service.py`, `services/llm_provider.py`). Only relevant passages are sent. They are numbered, HTML-escaped and wrapped in `<untrusted_document_context>` tags, and the question goes in `<user_question>` tags. The system prompt tells the model to treat both as data. The model replies in JSON, enforced by a strict schema on Cerebras.
- **Citations** (`services/citation_validator.py`, `validate_against_passages`). The model names a `passage_id` and a verbatim `quote`. A citation is built only if the quote appears verbatim in that retrieved passage; the comparison ignores differences in whitespace, case and dash style. The rule number, page and title come from the passage record. If no citation survives, the generated answer is withheld and `insufficient_evidence` is set to `true`.

## Document coverage and freshness

- The only regulatory source in this repository is the Government of MP's consolidation of the rules up to **6 March 2025** (`data/resources/*.pdf`, downloaded 9 and 10 Oct 2026 per `data/DATA_DICTIONARY.md`).
- **Known later change:** `data/DATA_DICTIONARY.md` records an amendment to **Rule 2(5)(c) dated 28 Aug 2026** that is not in the collection. The `PROBLEM.md` it refers to is not in this repository, and the amended text is not available here. The backend flags this amendment, by provision and date only, whenever Rule 2 is cited or a question refers to dates after the coverage date (e.g. sample question 11). It never paraphrases the amended text.
- **Unresolved:** the repository has no authoritative source for any other amendment after March 2025. Answers describe the rules **as consolidated on 2025-03-06** and do not claim that a provision is in force today. `GET /api/coverage` exposes these limitations to the UI.

To register another verified amendment, add a `KnownAmendment` to `services/coverage.py` with its source.

## Known limitations

- **Hindi source text.** The Hindi PDF uses a legacy Kruti Dev font encoding: text extraction returns Latin glyphs such as `fu;e` for नियम, with no Unicode Devanagari. It is therefore not indexed. Hindi questions are answered from the English text, and excerpts are quoted in English.
- **Retrieval-only mode** cannot judge relevance as well as an LLM. It only serves passages above a score floor, and for some Hindi questions the best passage is not ranked first (e.g. sample question 14 ranks Rule 57 above Rule 56).
- **Tables are flattened** in the source data, so cells from neighbouring columns interleave. When a model quotes one table cell, the validator accepts it only as at most 3 close, ordered, verbatim fragments; the excerpt is shown as those fragments joined by "…", and confidence is capped at `medium`. Check figures from tables against the PDF page given in the citation.
- **Passages carry lead-in text.** Each passage sent to the model includes the lines just before it in the same rule, so it can tell, for example, the application fee (Rule 21(2)) from the high-rise permission fee (Rule 21(3)(c)).
- The number check covers decimals and integers followed by a unit. A bare integer in an answer, such as "two", "3" or a clause number, is not verified.
